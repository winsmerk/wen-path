# wen-path 内容管理与生词复习更新 Plan

日期：2026-09-26
状态：U1–U4 已实现并通过本机验证，正在发布。U5 的 Codex 浏览器写入已验证，普通 ChatGPT 远程连接尚未接通。

## 1. 本轮目标与边界

1. 记录模块独立管理个人记录，仅保留读书笔记、灵感、日记三类。
2. 取消记录与任务的关联功能：记录不因任务完成而创建，保存记录不改变任务状态。
3. 新增英语生词表，保存每日聊天整理的词汇、释义和造句，提供记忆检查与易忘词管理。
4. 新增自媒体模块，分小红书、海外自媒体；各自包含选题灵感和文案定稿。
5. 移除备忘录和工具模块，并停用备忘录提醒。
6. 接入明确的聊天归档指令，将选定的定稿写入网站。

保留今日、愿景、征程、计划、财务和复盘的独立功能。不恢复已经移除的“今天的工作台”。原英语日记不再是独立记录类型，英文正文可保存在“日记”中。Kinikini 自动进度同步与图片划线识别属于旧计划的后续事项，不是本轮验收前提。

## 2. 导航与内容结构

| 入口 | 内部结构 | 主要内容 |
| --- | --- | --- |
| 记录 | 读书笔记、灵感、日记 | 标题、正文、日期、图片 |
| 英语生词表 | 全部词表、待复习词、易忘词、已掌握、检查历史 | 每日词表、词汇释义、造句与复习结果 |
| 自媒体 | 小红书 / 海外自媒体 → 灵感 / 文案 | 选题、讨论摘要、最终文案 |
| 原有入口 | 今日、愿景、征程、计划、财务、复盘 | 保留独立功能 |

“全部”若用作汇总筛选，不算第四种记录类型。记录页新增、编辑、统计与筛选均只能使用三类，不再跟随任务类型自动扩展。移动端同步调整导航，保证新增入口可达。

## 3. 独立记录及任务脱钩

### 3.1 记录规则

- 类型固定为 `reading_note`（读书笔记）、`inspiration`（灵感）、`diary`（日记）。
- 支持独立新增、编辑、删除、日期与分类筛选及图片查看；沿用现有图片上传能力。
- 不显示或提交任务 ID、任务完成时间、任务类型等关联字段。
- 日记允许中英文正文，不单列“英语日记”。自媒体灵感与个人灵感分别存储，不自动混合。

### 3.2 去除任务关联功能

- 移除任务完成时的“保存记录并完成”、记录类型选择、记录正文及图片上传流程。
- 任务改为直接完成/恢复未完成；不要求记录作为前置条件。
- 任务定义删除“建议记录/要求记录”的设置和提示。
- 记录模块停止聚合任务输出、打卡和计划任务记录；仅展示独立记录。
- 停止记录保存、编辑、删除时对任务状态或进度的联动；进度仅由任务自身状态计算。
- 移除客户端对关联记录接口的调用，关闭旧接口的关联写入路径，避免旧客户端继续触发联动。
- 移除任务响应中专为记录关联提供的字段和查询（如 record_id、record_required），同步更新类型和既有测试。
- 存量关联字段及旧表先作为迁移历史保留，不在首版上线时直接删表。最终用户功能中不存在关联入口。

### 3.3 存量数据迁移

先读取生产数据生成迁移清单：来源表、记录 ID、标题、原分类、附件数量、建议归属。已核实生产存量 10 条：读书笔记 1、个人灵感 5、日记 3、小红书文案 1；无附件。用户已确认南瓜文案与健康日记的归属。

1. 精确定位用户指定的一条“学习记录”，转为独立读书笔记；保留内容、原发生日期和全部附件。不得把所有学习内容一律改为读书笔记。
2. 已有日记和个人灵感保留原分类；明确的读书笔记归入读书笔记，已有英文日记归入日记。
3. 其他历史任务成果按内容整理：自媒体内容转入对应自媒体板块；可确定的个人记录转为三类之一；无法判断的条目列入迁移清单，待核对后完成归类，不强制塞入日记或丢弃。
4. 迁移复制正文和附件引用，生成独立记录 ID；旧附件访问校验适配新的所有权关系。历史任务的完成状态保持不变。
5. 以“用户 + 来源表 + 来源 ID”保证迁移幂等；该来源映射只用于内部迁移审计，不向用户暴露任务关联。
6. 上线前备份，核对条目数、附件数及内容；全部存量处理完毕后才切换旧聚合视图。迁移失败可恢复旧版本及映射。

验收：三类之外不能新增记录；完成任务不生成记录；保存/删除记录不改变任务；指定学习记录完整显示为读书笔记；历史内容与图片无丢失、无重复。

## 4. 英语生词表

### 4.1 词表与词条

- 每日可创建多份词表，包含日期、标题、聊天来源说明和词条；提供全部词表列表、日期筛选和词汇搜索。
- 一个词条包含单词/短语、词性、中文释义、来源语境及一个或多个造句；造句可标明用户原句、聊天修订句及说明。
- 相同词元与词性复用词条，不丢失不同日期、不同词表的来源和例句；不确定的词形由用户核对后合并。
- 首版支持手工录入和粘贴结构化词表，预览后保存；聊天直接归档由第 6 节接入。
- 词表详情保留历史收录情况；“已掌握”词带状态展示，默认不进入活动生词列表。

### 4.2 记忆检查流程

1. 支持点击一个词发起单词检查，也支持选择检查范围（全部待复习词或某份词表）。
2. 用户自定义检查数量 N，范围为 1 至当前可检查的去重词数；空词库不能开始，超出数量时明确提示。
3. 生成不重复的检查列表；优先抽取易忘词，其余从候选词中随机补足。检查开始后固定列表，刷新可继续。
4. 每题最初只显示单词，不展示释义、例句翻译或会泄露答案的提示；用户回忆后选择“记得”或“忘记”，两项互斥。
5. 作答后展示释义和造句用于核对，再进入下一词。允许在提交本轮之前改选，最终每题只计入一次。
6. 本轮提交保存结果，展示记得/忘记数量及建议复习词；中途退出保留未完成进度，不把未答题计为忘记。

### 4.3 易忘和掌握规则（首版默认）

- 保存每词累计检查次数、累计忘记次数、最近检查结果及日期。
- “频繁忘记”定义为最近 5 次有效检查中至少 3 次忘记；检查少于 5 次时，至少累计 3 次忘记才标记。
- 活动词表默认排序：易忘标记优先 → 最近 5 次忘记次数降序 → 累计忘记次数降序 → 最近检查日期升序（未检查优先）→ 稳定词条 ID。
- 易忘标记随新结果重新计算，不永久贴标签；各词表详情也沿用易忘优先排序。
- 一次选择“记得”不等于完全掌握。用户可以另行点击“完全记住”，将词移入“已掌握”，从活动词表和新检查候选中移除。
- 移除采用归档，不永久删除词条、来源、造句或检查历史；支持从“已掌握”恢复复习。
- 进行中的检查若词被归档，提示跳过并调整本轮有效题数，不伪造检查结果。

验收：答案默认隐藏；检查数量正确、无重复；记得/忘记互斥；重复提交不重复累计；易忘排序可验证；已掌握词不再出题且可恢复；每日多词表共享词条但不丢例句。

## 5. 自媒体

| 平台分区 | 灵感板块 | 文案板块 |
| --- | --- | --- |
| 小红书 | 选题、切入点、素材、讨论摘要 | 最终标题、正文、话题标签、配图及版本 |
| 海外自媒体 | 平台/账号、选题、受众、语言、素材 | 最终标题、正文/脚本、标签、语言及版本 |

- 两个平台分区独立筛选与保存，海外记录支持填写具体平台和账号。
- 灵感状态：待讨论、已选用、已归档；可以由灵感创建文案并保留来源引用，不与任务关联。
- 文案区主要展示定稿。网站编辑可暂存草稿，明确区分草稿与定稿。
- 定稿修改生成新版本，保留旧版本；相同指令重试不重复建档。
- 定稿不等于已发布。发布状态、实际发布时间与发布链接单独记录；本轮不自动发布到社交平台。
- 搜索与筛选支持平台、日期、标题、状态。个人记录中的“灵感”与这里的“选题灵感”在聊天归档时明确区分。

## 6. 聊天定稿写入 wen-path

用户目标指令示例：

> 当前内容已确定，请帮我记录到 wen-path 网站小红书文案记录中。

目标流程：识别当前已选定的正文 → 确定平台与归档位置 → 调用经认证的写入工具 → 网站持久化 → 返回记录标题、归属、记录 ID 和可打开的详情链接。

- 明确的小红书文案指令直接写入“小红书 / 文案”，状态为定稿，不必重复询问已确定的信息。
- 指令未指明目标、含多个候选版本或正文不完整时，只补问缺失信息；不能擅自选择稿件。
- 生词指令保存词表、释义与造句；日记或读书笔记指令保存独立记录；所有入口使用同一套持久化规则。
- 保存失败返回失败信息和可重试方式，不能回复“已记录”；禁止把仅生成 Markdown 当作网站保存成功。
- 重试使用同一 request_id；更新已有定稿时使用记录 ID 与版本，冲突不静默覆盖。
- 不后台抓取全部聊天；只提交当前明确选定的内容，聊天链接只是可选来源。

### 接入可行性检查与交付顺序

1. 先核实当前用户使用的聊天入口能否连接该私有网站的认证写入工具，以及 Sites 支持的接口与身份方式。
2. 设计网站写入 API 与可供聊天调用的工具适配（是否采用 MCP 或其他受支持连接方式，在核实后确定）。所有写入从服务端确认用户身份，不信任客户端传入的 user_id。
3. 分别验证“从当前 Codex 任务写入”与“从用户平时使用的 ChatGPT 对话写入”；前者可用不能代替后者验收。
4. 接入未完成时先交付网站粘贴导入入口，明确标记为过渡方案；聊天直接归档仍保持待完成，不宣称普通聊天已能自动写入。
5. 若需要用户连接账户，功能和权限范围准备好后再提供连接步骤；不将密钥放进对话或前端。

聊天直写是独立验收项，必须用一条实际定稿指令完成端到端验证，不能仅凭接口测试宣布完成。

## 7. 移除备忘录与工具

- 删除桌面、移动端导航项与页面入口，清理无用组件、轮询及相关客户端请求。
- 备忘录：停止后台 scheduled 分发和 API 中的提醒触发；核查并停用仅服务该模块的云端调度，避免页面消失后继续发提醒。
- 工具：移除工具页、英语 Coach/录音入口及其专用接口调用；检查服务端写入路径并关闭停用功能。
- 备忘录历史和英语对话历史先保留，不自动删除；它们不迁入新生词表，除非用户明确选择内容。
- 网站其他功能如仍依赖某项配置，不删除共享配置；历史表删除作为后续独立清理，不属于本次默认动作。

验收：导航与页面不再显示这两项；旧入口不能继续使用；不再自动发送备忘录提醒；其他模块正常。

## 8. 数据与接口设计方向

复用 D1 保存结构化数据、现有媒体存储保存图片；具体 schema 在实施前核定。增量迁移，不改写已应用的迁移历史。

| 数据域 | 建议数据实体 | 关键约束 |
| --- | --- | --- |
| 独立记录 | 现有 journal_entries / journal_images + 内部迁移映射 | 三类校验；无任务关联；来源迁移幂等 |
| 生词 | 词表、词条、词表成员、例句/来源 | 同用户词条去重；多来源；掌握状态 |
| 检查 | 检查会话、检查题目、最终结果 | 题目快照；每题一次计数；可恢复 |
| 自媒体 | 选题、文案、文案版本、媒体引用 | 平台隔离；定稿版本；可选灵感来源 |
| 聊天导入 | 导入请求与结果映射 | 用户隔离；request_id 唯一；版本冲突检测 |

服务端统一校验分类、日期、内容长度、数量和归属；列表分页，排序稳定。媒体和记录同用户授权，错误不清空输入。去掉记录与任务关联不影响其他领域正常的从属关系（例如词表与词条、灵感与文案）。
